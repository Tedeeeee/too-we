# 꽃갈피 선택 화면 SVG 및 선택 상태 설계

## 목표

꽃갈피 선택 바텀시트를 참고 이미지와 동일한 구성으로 정리한다. 등록된 꽃 7종의 원본 SVG를 각 선택 항목에 표시하고, 기록에 저장된 꽃갈피 유무에 따라 초기 선택 상태를 결정한다.

## 검토한 방식

1. **기록 데이터에서 초기 선택값을 직접 읽기 — 채택**
   - 선택 화면이 `recordId`로 현재 기록을 조회하고 `record.flower`를 초기 선택값으로 사용한다.
   - 경로 전환 중 별도 데이터가 복제되지 않아 실제 저장 상태와 화면이 일치한다.

2. 경로 상태로 `initialFlower` 전달
   - 구현은 단순하지만 호출부마다 값을 넘겨야 하고 기록 데이터와 경로 상태가 어긋날 수 있다.

3. 신규 선택과 수정 선택을 별도 화면으로 분리
   - 동작은 명확하지만 동일한 UI와 저장 로직이 중복되므로 현재 범위에는 불필요하다.

## 화면 구성

- 기존 402px 모바일 바텀시트와 2열 그리드 구조를 유지한다.
- `FLOWERS`의 7개 항목을 순서대로 표시한다.
- 각 항목은 꽃 이름, 꽃말, `flowerSvg[f.key]` 원본 SVG로 구성한다.
- 선택된 항목만 연한 올리브 배경과 올리브 테두리를 표시한다.
- 하단 확인 버튼은 스크롤과 분리해 고정한다.
- 실제 꽃 SVG 안에 줄기와 테이프가 포함되어 있으므로 공용 평가 꽃 아이콘과 별도 테이프 도형은 제거한다.

## 선택 상태와 데이터 흐름

- 기록의 `flower`가 `null`이면 선택 없이 진입한다.
- 기록에 꽃 key가 있으면 해당 꽃을 선택한 상태로 진입한다.
- 선택되지 않은 항목을 누르면 해당 꽃 하나가 선택된다.
- 선택된 항목을 다시 누르면 선택값이 `null`로 바뀐다.
- 다른 꽃을 누르면 기존 선택이 해제되고 새 꽃이 선택된다.
- 확인 버튼을 누르면 선택된 key 또는 `null`을 `setRecordFlower`에 전달한다.
- 저장 성공 후 기존 장소 상세 화면으로 돌아간다.

## 예외 처리

- 존재하지 않는 `recordId`면 기존 안전 경로로 이동한다.
- 기록의 `flower`가 등록된 `FLOWERS` key와 일치하지 않으면 미선택 상태로 취급한다.
- 저장 중에는 중복 확인을 막는다.
- 저장 실패 시 화면을 유지해 현재 선택을 잃지 않도록 한다.

## 검증

- 선택 화면에서 `flowerSvg[f.key]`를 사용하는지 자동 검사한다.
- 꽃갈피가 없는 기록은 초기 선택이 `null`인지 확인한다.
- 기존 꽃갈피가 있는 기록은 해당 꽃으로 초기화되는지 확인한다.
- 같은 꽃 재클릭 시 `null`, 다른 꽃 클릭 시 새 key가 되는지 확인한다.
- `null`도 저장 가능한 값인지 확인한다.
- SVG 검증, UI SVG 검증, 프로덕션 빌드를 실행한다.
