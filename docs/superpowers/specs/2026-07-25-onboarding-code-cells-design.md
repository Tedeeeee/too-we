# 온보딩 입력 요소 정렬 디자인

## 목표

초대 코드 숫자와 손그림 밑줄의 중심이 어긋나는 문제를 제거하고, 이름 입력 글자와 밑줄 사이의 과도한 간격을 줄인다.

## 원인

현재 숫자는 하나의 텍스트 노드에 `letter-spacing`을 적용하고, 밑줄은 별도의 6칸 flex 레이아웃으로 렌더링한다. 두 레이아웃은 글꼴 폭과 flex 계산 방식이 달라 같은 중심을 공유하지 않는다.

## 구조

- 358px 영역을 간격 10px의 동일한 6칸으로 나눈다.
- 각 칸은 숫자 표시 영역과 `HandDrawnLine`을 함께 포함한다.
- `code[i]`가 존재하면 해당 칸 중앙에 숫자를 표시한다.
- 빈 칸은 숫자 없이 손그림 밑줄만 표시한다.
- 입력 완료 칸과 현재 입력 칸의 선 상태 표현은 기존 동작을 유지한다.

## 이름 입력 간격

- 이름 입력 필드와 입력 글자의 위치는 유지한다.
- 긴 손그림 밑줄을 기존 위치에서 28px 위로 이동한다.
- 글자 수 표시도 함께 28px 위로 이동해 밑줄과의 기존 간격을 유지한다.
- 안내 문구와 하단 버튼 위치는 변경하지 않는다.

## 배치

- 전체 6칸 컨테이너는 기존 숫자와 밑줄 영역을 합친 범위에 놓는다.
- 각 숫자는 해당 칸의 가로 중앙에 정렬한다.
- 각 밑줄은 셀 내부 `top: 73`에 배치해 화면 기준 y=465부터 보이게 한다.
- 숫자 위치는 유지하고 밑줄만 기존 위치보다 28px 위로 이동한다.
- 이름 화면의 밑줄 중심은 y=499에서 y=471로 이동한다.
- 제목, 안내 문구, 숨겨진 입력, 연결 버튼 위치는 변경하지 않는다.

## 동작

- 기존 숨겨진 숫자 입력을 유지한다.
- 숫자만 허용하고 최대 6자리로 제한하는 로직을 유지한다.
- 6자리 입력 전 버튼 비활성화와 연결 동작을 유지한다.

## 검증

- 기존 단일 `{code}` 표시와 `letterSpacing: 22`가 제거되었는지 검사한다.
- 동일한 반복문 안에서 `code[i]`와 `HandDrawnLine`이 함께 렌더링되는지 검사한다.
- 한 자리와 여섯 자리 상태를 402×874 화면에서 확인한다.
- 각 숫자의 중심과 대응 밑줄의 중심이 일치하는지 브라우저 좌표로 확인한다.
- 코드 밑줄의 화면 좌표가 `top=465`인지 확인한다.
- 이름 화면에서 밑줄과 글자 수 표시가 각각 정확히 28px 위로 이동했는지 확인한다.
- SVG 사용 검사와 프로덕션 빌드를 실행한다.
